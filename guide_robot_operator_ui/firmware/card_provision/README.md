# card_provision — выпуск карт операторов

Утилита персонализации карт для `rfid_bridge`. Прошивается **на ту же
плату с тем же RC522** — отдельного железа не нужно. После выпуска карт
вернуть `rfid_bridge`.

Что делает: пишет в сектор 1 карты MIFARE Classic 1K логическое имя
оператора (блок 4) и меняет ключ A сектора с заводского `FFFFFFFFFFFF` на
`RFID_SECTOR_KEY` (блок 7, trailer). Ровно то, что потом читает
`rfid_bridge::readOperatorName()`.

## Перед первым запуском

```bash
../tools/gen_secrets.sh
```

Генерирует `include/card_provision_secrets.h` из того же
`~/.config/guide_robot/rfid_sector_key`, что и заголовок моста. Ключи в
двух прошивках обязаны совпадать, иначе выпущенные карты мост не
прочитает.

## Прошить утилиту

```bash
pio run -t clean && pio run -t upload
pio device monitor
```

При старте печатается `VersionReg` — заодно проверка SPI:

- `0x88` — FM17522, клон, нормально
- `0x91` / `0x92` — оригинал MFRC522
- `0x00` / `0xFF` — SPI не работает; проверь SS→10, MISO→13, питание 3.3 В и общую землю

У утилиты отдельный `USB_SERIAL` (`guide-robot-card-provision`), поэтому
пока она залита, плата **не** матчится udev-правилом ридера и `/dev/rfid0`
не появляется. Это нарочно: узел иначе открыл бы REPL прошивальщика.

## Команды

Набираются в `pio device monitor`, по одной на строку.

| Команда | Что делает |
|---|---|
| `verify` | читает карту, ничего не меняя |
| `write <имя>` | прошивает **чистую** карту: имя + смена ключа |
| `rename <имя>` | меняет имя на уже прошитой карте, ключ не трогает |
| `help` | список команд |

Имя — ASCII, до 16 символов. Оно уйдёт в поле `"card"` протокола и в
jsonl-лог как `operator`. Соглашение: `op_<логин>`, например `op_mook`.

## Выпуск карты

```
write op_mook
```

Поднеси чистую карту. Ожидаемый вывод:

```
   блок 4 записан
   trailer записан, ключ сменён
Записано. Проверь: убери карту, поднеси заново, набери 'verify'.
```

Затем **убери карту из поля и поднеси заново** (иначе она в состоянии HALT
и на REQA не ответит), и:

```
verify
```

Ждём `OK: прошитая карта, имя = 'op_mook'`.

Дальше следующая карта: `write op_fabian`, и так далее.

## Если что-то пошло не так

**`сектор 1 не открылся заводским ключом`** — карта уже персонализирована
или это не MIFARE Classic 1K. Ничего не записано, карта цела. Для смены
имени используй `rename`.

**`не открылась рабочим ключом`** на `verify`, при том что и заводской не
подошёл — сверь ключи:

```bash
grep -A2 RFID_SECTOR_KEY include/card_provision_secrets.h
cat ~/.config/guide_robot/rfid_sector_key
```

**`карта не появилась за 20 с`** — дальность FM17522 2–3 см, толстая карта
её съедает. Клади карту вплотную на антенну, води туда-обратно.

**Ошибка на записи блока 4** — ключ ещё не менялся, карта полностью
восстановима. Порядок записи (сначала имя, потом ключ) выбран именно ради
этого.

**Ошибка на записи trailer** — ключ мог смениться частично. Проверь
`verify` до выдачи карты.

## Байты доступа — не трогать

В `src/main.cpp` trailer собирается как
`<KEY_A 6> FF 07 80 69 <KEY_B 6>`. `FF 07 80 69` — заводская конфигурация
access bits. Любое другое значение может **необратимо** закирпичить сектор
1: ни прочитать, ни переписать его будет нельзя никаким ключом. Меняй что
угодно, кроме этих четырёх байт.

## Потеря ключа

`~/.config/guide_robot/rfid_sector_key` невосстановим. Потеряешь — все
выпущенные им карты станут нечитаемыми навсегда, включая для тебя.
`gen_secrets.sh` намеренно не перезаписывает существующий ключ.

Храни копию вне машины.
