# Независимый API управления Robo-guide v1

Публичный адрес: `http://127.0.0.1:8089/api/v1`. Контракт: `openapi.json`.
Документация без CDN: `/api/v1/docs/index.html`. WebSocket: `/api/v1/events`.
Хостовый сервис `guide_launcher` не импортирует ROS и работает с выключенным стеком.
ROS-адаптер `guide_robot_api` слушает только loopback:8091. Его token не передаётся клиентам.

## Сессия и политика посетителя

POST `auth/challenge` выдаёт одноразовый nonce на 30 секунд. POST `auth/verify`
принимает `{nonce, backend: "pin", pin}` либо `{nonce, backend: "rfid"}`.
RFID использует считыватель робота. Cookie `gl_session` — HttpOnly, SameSite=Strict.
TTL по умолчанию 600 секунд, успешные авторизованные POST продлевают его; GET не продлевают.
Одновременно действует одна операторская сессия. POST `auth/logout` завершает её.

Управление и обслуживание требуют сессии. Чтение состояния/каталога и событий открыто локально.
Посетителю доступны только `public/stop` и `public/confirm`.
`public/start-tour` всегда возвращает 403; запуск требует сессии через `missions`.
`public_tours` сохранён для чтения старых конфигураций, но больше не разрешает запуск.
`visitor_confirm_buttons` запрещает/разрешает публичный ответ. Стоп посетителя допускается
только при свежем состоянии движения. Проверки выполняет сервер, независимо от кнопок UI.
CORS выключен по умолчанию; `allowed_origins` допускает только явно перечисленные
loopback origins с credentials. Wildcard запрещён. Для разработки предпочтителен один hostname.

## Команды и операции

`missions` принимает ровно один из `tour_id` и `location_ids`. Значения по умолчанию:
start_index=0, time_budget_min=0 (без бюджета), greet=true, narrate=true,
confirm_between_stops=false, return_home=true. Предпочтение тура панели не влияет на эти значения.
`missions/go-to` принимает location_id и запускает RunTour из одной точки без приветствия,
рассказа и возврата. FSM проверяет существование/допустимость маршрута.

`missions/stop` останавливает на месте. `interaction/confirm` с answer=stop завершает
тур по правилам FSM, включая возврат, если он включён. `missions/return` и `missions/base`
используют существующий сервис возврата: его ответ означает принятие, а движение видно
в состоянии миссии; action-result для него не обещается.

POST `missions`, `missions/go-to`, `speech`, `public/start-tour` требуют Idempotency-Key.
Одинаковые ключ и нормализованные параметры в одной сессии/экземпляре дают ту же операцию.
Другие параметры с тем же ключом дают 409. Реестр ограничен 256 операциями; ключи не вытесняются
до рестарта, при заполнении новые операции отклоняются. Это осознанный предел v1.
API не восстанавливает и не повторяет команды после рестарта. Сохраните ключ перед отправкой.

202 не означает завершение: операция проходит pending → running → succeeded/failed/canceled/rejected.
Потеря свежего upstream, перезапуск моста или таймаут отправки дают unknown. Позднее состояние
не превращает unknown автоматически в успех. Повтор с прежним ключом безопасно читает тот же
результат; новый ключ может запустить второе действие. Отмена разрешена сессии-создателю.
Speech — обычный Say: priority=100, scope=dialog, interruptible=true, max_duration=120 (1..300 сек).

Face override: state, duration_s (0.1..60), gaze_az (-90..90, по умолчанию 0).
Монотонный срок контролирует ROS-агрегатор. Авария и движение имеют приоритет; clear/истечение
возвращают автоматический выбор. Фактические state/gaze/source находятся в robot.face.

## Состояние и события

Health подтверждает только хост, не вызывает ListTours. Snapshot различает transport_connected,
data_fresh и robot.readiness. robot=null означает отсутствие свежего кадра (порог 3 секунды).
Возраст mission_state_age_s включает время после получения ROS mission/state и ожидание кадра на хосте.
instance_id присутствует и в HTTP state. moving учитывает движение во время answering;
base_state_name сообщает прерванное диалогом состояние.
Список available_commands публикует FSM; это подсказка, команда повторно проверяется при исполнении.

Каждый WS-конверт содержит type, instance_id, seq и data. Seq возрастает в экземпляре;
пропуски допустимы, в том числе из-за подключения другого клиента. Snapshot приходит при каждом
подключении; state и heartbeat несут полный снимок и операции с последним feedback/result.
Частые feedback объединяются с частотой 1 Гц. История событий не переигрывается.
При новом instance_id клиент сбрасывает старые операции и заново читает состояние.

Ошибки: `{error: {code, message, request_id}}`, X-Request-ID.
400 invalid_arguments; 401 auth_required; 403 forbidden; 409 invalid_state;
502/503 subsystem_unavailable; 504 outcome_unknown; 500 internal_error.
Не повторяйте автоматически команды после таймаута. Для сервисных команд смотрите состояние.
Ответ сервисной команды содержит последний наблюдаемый state, в том числе при отказе ROS;
это снимок с собственной свежестью, а не обещание синхронной публикации нового состояния.
Медиа поддерживает Range; успешные файлы кэшируются 30 секунд, ошибочные ответы — no-store.

## Установка и миграция

Обновлять одной версией host, guide_robot_msgs, guide_robot_api, mission_control, face и reference_ui.
Сначала остановить миссию и подтвердить idle. Остановить старые процессы, пересобрать workspace
(изолированный install предпочтителен; старый guide_robot_operator_ui не должен оставаться в overlay),
обновить launcher через scripts/jetson-launcher/install.sh и конфигурацию по config.example.yaml.
Установщик сохраняет существующий config: вручную добавить serve_ui/public_tours/web_dir и новый
promo_dir. Старые HTTP-маршруты удалены. Старый /face/set_state удалён, используйте /face/override.
Прошивки перенесены в firmware/operator_rfid. Firefox/WebKit kiosk и порт глаз 8090 сохранены.

`serve_ui: false` отключает штатную статику и её настройки. API запускается без reference_ui.
Для своего UI задайте serve_ui=true и web_dir на свою сборку (index.html + /static).
Маршруты reference/* — необязательные предпочтения/промо эталонного клиента, не правила робота.
Независимый пример: `python3 examples/api/client.py --tour expo_one --stop-after 10`.
Без --tour он только входит и читает состояние/каталог. PIN запрашивается интерактивно.

## Карта и системные настройки

`map` возвращает текущую OccupancyGrid и TF-положение; `map/image` — PNG.
Поза `x/y/yaw` задаётся в метрах/радианах системы карты. go-to-pose требует
map_version и ключ идемпотентности; неизвестные/занятые клетки отклоняются.
Все поездки проходят общий слот mission FSM, без обхода safety.
localization/reset принимает confirm=true и либо pose+map_version, либо preset_id;
без селектора используется первая доступная настроенная точка. Публикация начальной
позы и подтверждение очистки костмапов сообщаются отдельно; AMCL convergence не обещается.

`audio/output` регулирует весь выход в процентах разрешённого диапазона (по умолчанию
100 на слайдере соответствует 20% Pulse). `wifi` и системный звук обслуживает хост
через локальные Unix sockets; отсутствие помощника означает недоступность функции.
Wi-Fi connect возвращает операцию, включает одну попытку восстановления прежней сети.
Пароли отсутствуют в событиях, журнале и сохранённом payload операции.
См. scripts/jetson-launcher/helpers/README.md для настройки системных служб.
## Свежесть локализации после простоя

В простое ROS запрашивает обновление AMCL раз в пять минут. Если локализация
`ready`, но `fresh=false` и `reset_required=false`, команда движения передаётся
в ROS для проверки свежей оценки перед принятием. Без подтверждения свежести
движение запрещено. При `lost`/`recovering` требуется восстановление оператором.
После задания позиции превышение порогов не прерывает восстановление раньше
15-секундного таймаута; движение остаётся заблокированным до успешной проверки.

RFID: штатный клиент по нажатию открывает 30-секундное окно ожидания.
Последовательно запрашивает новый nonce и auth/verify с backend=rfid,
с паузой 500 мс после ответа rfid_no_card. Этот ответ (HTTP401,
error.message=rfid_no_card) не увеличивает счётчик неверных входов; неверная
подпись и PIN по-прежнему учитываются. Отмена/таймаут прекращают опрос.
Успех запроса, уже выполнявшегося при отмене, закрывается через auth/logout.

Ориентация карты: robot_pose, target и задаваемые позы — положение
base_footprint в map. +X направлен к роликам (направление движения),
а не к экрану. AMCL/Nav2 используют тот же base_footprint; yaw жеста
передаётся без добавления pi. В URDF base_link повёрнут относительно него на pi.

При startup_parking_check=true ROS однократно проверяет парковку после старта:
ожидание активного AMCL, свежего TF и сервисов костмапов до90с; затем новые
оценки после начала проверки, поза в пределах0.5м/20° от startup_parking_pose,
ковариация <=0.35м/15°, минимум3 сообщения за >=2с, обе очистки костмапов.
Окно подтверждения15с. Успех снимает сохранённую блокировку локализации;
ошибка оставляет lost, повтор восстановления только оператором. Во время
проверки state=initializing/recovering, reason=startup_waiting_for_amcl или
startup_checking_parking. Estop и остальные блокировки не снимаются.
Это настройка площадки с предположением физического старта на парковке;
уверенно ошибочную оценку AMCL одна такая проверка обнаружить не может.
