# guide_robot_voice

Аудио-I/O робота-экскурсовода. О туре и об экспонатах пакет не знает ничего.

## Отличия от исходной спецификации

Пять правок контракта. Каждая либо закрывает гонку, либо делает заявленное
требование измеримым.

| Было | Стало | Почему |
|---|---|---|
| `/speech/cancel_all` — `std_msgs/Empty` | `CancelAll{epoch, scope, reason}` | Без `epoch` чанк, синтезированный за миллисекунды до отмены, доигрывается после неё. Без `scope` нельзя прервать монолог, не убив ответ на вопрос |
| `/asr/transcript` — один топик | `/asr/partial` (BEST_EFFORT d1) + `/asr/transcript` (RELIABLE d10) | Партиалы идут 5–10 Гц и волатильны. В RELIABLE-очереди с командами они дают разрастание очереди и head-of-line blocking |
| `/voice/is_speaking` — `Bool` | `SpeakingStatus{stamp, speaking, epoch, expected_end, …}` | Latched `Bool` при падении ноды навсегда застревает в `true` |
| `/speech/wakeword` — `String` | `Wakeword{keyword, confidence, tts_active}` | Без `confidence` и `tts_active` не считается false-wake rate — приёмочная метрика пакета |
| `Say.action` без приоритетов | `priority`, `interruptible`, `scope`; `Result.spoken_chars` | Аварийное «отойдите» не должно прерываться посетителем. `spoken_chars` позволяет `narration_server` возобновить монолог с места обрыва |

## Требование <200 мс: две метрики вместо одной

Исходная формулировка неизмерима, потому что смешивает разное.

| | Что мерить | Цель | Узкое место |
|---|---|---|---|
| `t_stop` | publish `cancel_all` → тишина в динамике | <100 мс | глубина буфера ALSA |
| `t_bargein` | онсет речи человека → тишина | <400 мс | детектор (VAD/wakeword) |

`t_stop` измеряется `tools/measure_t_stop.py`. Софтовая часть (от `bump()` до
возврата `abort()`) — доли миллисекунды и проверяется в CI как регрессионный
порог. Акустическая часть снимается **внешним микрофоном**, который пишет
и щелчок синхронизации, и динамик робота на одну дорожку: иначе измеряется
рассинхрон часов, а не отмена.

## Инвариант fencing

> После возврата `bump()` в устройство может попасть **не более одного**
> устаревшего чанка — того, что уже был в полёте.

Формулировка именно такая, а не «ни одного». Писатель обязан входить
в блокирующий `write()` вне лока, иначе `bump()` ждал бы окончания
воспроизведения. Окно между последней проверкой `epoch` и входом в `write()`
принципиально ненулевое.

Отсюда `block_ms = 20`, а не 200: длительность блока — верхняя граница
остатка, который `snd_pcm_drop` обязан убить в устройстве.

## Чего здесь нет и почему

**AEC.** Программный AEC поверх ROS — худший из вариантов: ему нужен
reference, синхронный с захватом до сэмпла, а всё, прошедшее через DDS,
эту синхронность теряет. Решается уровнем ниже — аппаратно на XVF3800 либо
в PipeWire. Фронтенд открывает уже очищенный source.

**Семантический end-of-turn.** `turn_detector` реализован как адаптивный
таймаут. Для экскурсионных вопросов («а сколько ему лет?») 600–800 мс
поверх Silero закрывают задачу целиком; семантический EOU экономит ~300 мс
на длинных фразах с паузой посередине. Точка расширения — метод
`_timeout_for()`, интерфейс не меняется.

**C++ composable nodes.** Публикация 16 кГц PCM в топик — транспорт периода
разработки. Целевая форма — `audio_frontend` + `vad` + `wakeword` в одном
контейнере с intra-process comms и lock-free кольцевым буфером. Переносить
сейчас преждевременно: сначала железо и измеренный джиттер. Контракт наружу
при переносе не меняется.

## Работа без железа

`source: file` в `config/voice.yaml` подставляет `FileSource` вместо
устройства: WAV проигрывается в реальном времени как будто это микрофон.
Весь конвейер — VAD, wakeword, ASR, turn detection — прогоняется на записанном
материале детерминированно и на каждый коммит. Без этого false-wake rate
измеряется только вручную на роботе, то есть не измеряется.

`backend: null` в `tts_node` даёт синтез тоном известной частоты
с длительностью, пропорциональной длине текста. Это и режим CI, и стимул
для акустического измерения `t_stop`: момент обрыва тона виден
на осциллограмме с точностью до периода.

## Тесты

```bash
pytest test                    # 25 юнитов: чанкер, планировщик, fencing
python -m guide_robot_voice.tools.measure_t_stop --iterations 20
```

Юниты не требуют ни ROS, ни моделей, ни звуковой карты: вся логика,
которую есть смысл проверять, вынесена из нод в чистые модули.

## Параметры, помеченные ИЗМЕРИТЬ

В `config/voice.yaml` отмечены значения, подобранные из общих соображений.
Оставлять их после приезда железа нельзя: `buffer_ms`, пороги VAD,
`barge_in_min_speech_ms`, `threshold_under_tts`. Последний поднят
до 0.8 именно потому, что ERLE ещё не измерен.
