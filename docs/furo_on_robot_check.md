# Первая проверка у FURO-D

Цель этого сеанса — считать энкодеры и вручную отметить положения головы.
Драйвер ROS, прошивку и параметры контроллера не меняем.

## Ограничение передачи

На Jetson копируется только `scripts/furo_head_capture.py`. В нём ровно
одно место отправки в COM и один фиксированный пакет:

```text
FF FF 2E 04 03 A0 05 25
```

Этот пакет присутствует 87 раз в исходном реальном COM-логе робота.
В скрипте нет ввода произвольного hex, выбора регистра, команды движения,
записи PI/PID/лимитов, сброса, прошивки или входа в загрузчик.
Интерактивные `l/r/c/q` управляют только локальными отметками и завершением.

Не используем перебор ID/регистров/опкодов, широковещательное сканирование,
общую serial-консоль или неподтверждённые команды `55`. Найденные в DLL
запросы версии/состояния, управление током и позиционные команды тоже
не входят в первый сеанс. Наличие в старом софте не приравнивается к
подтверждённой поддержке установленным контроллером.

## Порядок на месте

1. Подключиться к Jetson и проверить модель/ОС, путь `/dev/tty_motors`,
   соответствующий USB–DB9 адаптер, владельцев COM-порта и процессы стека.
   ROS не запускать; проверить фактическое отсутствие автозапуска.
   Блокировка TIOCEXCL сама по себе не исключает процесс, открывший порт раньше.
2. Зафиксировать исходное состояние после холодной подачи питания:
   колёса и голова свободны или удерживаются. Робот стоит устойчиво,
   возможность быстро снять питание приводов доступна человеку рядом;
   закрытие SSH не считается гарантированным остановом контроллера.
3. Открыть порт **без передачи байтов** на 3 секунды:

   ```bash
   python3 ~/furo_head_capture.py --passive --duration 3 \
     --output ~/head-passive-$(date +%Y%m%d-%H%M%S)
   ```

   Отсутствие кадров и ненулевой код выхода в этом опыте ожидаемы,
   если контроллер молчит без опроса. Проверить по JSON `commands_sent: 0`.
   Вместе посмотреть, изменилось ли удержание от самого открытия COM:
   USB-адаптер может менять управляющие линии при открытии/закрытии.
4. Если состояние не изменилось неожиданно, запустить обычную запись:

   ```bash
   python3 ~/furo_head_capture.py \
     --output ~/head-capture-$(date +%Y%m%d-%H%M%S)
   ```

   Передаваемый пакет остаётся только фиксированным запросом из реального
   лога, каждые 200 мс. Сначала проверить валидные ответы, показания
   неподвижной головы и отсутствие неожиданного удержания/движения.
   При неожиданном изменении прекращаем опыт и разбираем сохранённый обмен,
   не подбираем следующие команды.
5. Вручную немного повернуть голову: убедиться, что меняется третье поле,
   а колёсные счётчики остаются неподвижными. Если голова сопротивляется,
   не преодолевать удержание силой и не пробовать наугад torque-off.
6. Снять левый предел (`l` + Enter), правый (`r`) и положение прямо (`c`),
   удерживая каждое положение около секунды. К механическому пределу
   подходить плавно, не прикладывать дополнительное усилие в упоре.
   Повторить проход для оценки повторяемости. При повторных отметках
   итоговый JSON хранит последние значения, полный проход остаётся в CSV.
7. Завершить `q`, проверить JSON/CSV и закрытие COM. Скопировать результаты
   на ноутбук. Только после освобождения порта можно отдельно возвращаться
   к штатному запуску ROS; capture-скрипт его сам не запускает.

По этим данным устанавливаются диапазон энкодера, его знак, центр и шум.
Градусы и соответствие шкалы команды шкале энкодера не угадываются.
Для первого программного движения головы потребуется отдельный ограниченный
опыт после ручной калибровки; он не совмещается с проверкой снятия тока колёс.

## Проверено до выезда

- Декодер восстановил все 429 кадров исходного COM-лога.
- Тесты через Linux PTY проверяют точный передаваемый запрос, отсутствие любых
  передач в passive, интерактивные отметки, таймаут, checksum и освобождение порта.
- На реальном Jetson и контроллере этот скрипт пока не запускался.

Классификация возможностей: [furo_d_controller_features.md](furo_d_controller_features.md).
