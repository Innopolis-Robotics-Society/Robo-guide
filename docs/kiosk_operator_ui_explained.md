# Киоск, показ картинок и интерфейс оператора — как это работает целиком

Документ описывает цепочку от физического экрана до ROS-сервисов: что запускает браузер на
Jetson, откуда берётся картинка на большом экране, что показывает страница и меню оператора и
в каких случаях экран остаётся пустым.

Соседние документы: `scripts/jetson-launcher/README.md` (установка, конфиг, состояния стека,
приёмка), `scripts/jetson-display/README.md` (донгл FL2000, weston, тач, режимы экрана,
известные аппаратные проблемы), `guide_robot_operator_ui/README.md` (мост ROS ↔ HTTP),
`guide_robot_face/README.md` (лицо робота).

---

## 1. Общая схема

```
  хост Jetson                                                   контейнер robo-guide-jetson-1
  ┌───────────────────────────────────────────┐                ┌──────────────────────────────────┐
  │ guide-launcher.service  :8089             │  X-Bridge-Token │ operator_ui_node  :8091 (мост)   │
  │  страница, промо, вход, текущий тур,      │ ───────────────→│  /mission/state, RunTour, медиа  │
  │  управление стеком (docker exec)          │ ←── /ws, GET ───│                                  │
  │        ↑                                  │                 │ face_node  :8090                 │
  │ kiosk-hdmi.service (WebKit GTK, Wayland)  │                 └──────────────────────────────────┘
  │  └─ weston-dlhdmi → донгл FL2000 → экран  │
  │ kiosk-face.service (firefox) → панель DP-1│ ── http://127.0.0.1:8090
  └───────────────────────────────────────────┘
```

Большой экран **не зависит от ROS-стека**: страницу, промо и вход отдаёт хостовый сервис
`guide-launcher`, который живёт под systemd (`Restart=always`). Мёртвый ROS — это промо на
экране и меню, в котором можно нажать «Запустить».

| Что | Экран | Служба на Jetson | Адрес |
|---|---|---|---|
| Показ, кнопка «Начать экскурсию», меню оператора | большой экран через донгл FL2000 | `weston-dlhdmi` + `kiosk-hdmi` + `guide-launcher` | `http://127.0.0.1:8089` |
| Лицо робота (два SVG-глаза) | встроенная панель DP-1 | `kiosk-face` (`face_node` в контейнере) | `http://127.0.0.1:8090` |

## 2. Сторона Jetson: как запускается киоск

Файлы киоска живут вне ROS-workspace, копии части из них — в `scripts/jetson-display/`.

| Роль | Где на Jetson |
|---|---|
| Компоситор на донгле | `weston-dlhdmi.service`, `/etc/xdg/weston-dlhdmi/weston.ini` |
| Браузер большого экрана | `kiosk-hdmi.service` → `/usr/local/bin/guide-kiosk-hdmi` (копия: `scripts/jetson-display/guide-kiosk-hdmi`) |
| Браузер лицевой панели | `kiosk-face.service` → `/usr/local/bin/guide-kiosk-face` |
| Страница и меню, сервис | `guide-launcher.service`, код в `/opt/guide-launcher`, конфиг `/etc/guide-launcher/config.yaml` |
| Адрес большого экрана | `/etc/guide-kiosk/url-hdmi` (fallback — `url`) |
| Адрес лицевой панели | `/etc/guide-kiosk/url` |

`kiosk-hdmi.service` объявляет `Requires=weston-dlhdmi.service` и `After=`; drop-in
`kiosk-hdmi.service.d/10-guide-launcher.conf` добавляет `After=`/`Wants=guide-launcher.service`.
Работает под пользователем `jetson` с `Nice=15`, `CPUWeight=20`,
`WEBKIT_DISABLE_COMPOSITING_MODE=1`, `LIBGL_ALWAYS_SOFTWARE=1` (программная отрисовка),
`Restart=always`. Ставит всё это `sudo scripts/jetson-launcher/install.sh`.

### 2.1 Порядок запуска

Раньше стек и нода поднимались руками, а киоск открывал страницу, которой ещё нет. Теперь
страницу отдаёт launcher, поэтому цепочка такая: `guide-launcher` → `kiosk-hdmi` открывает
`:8089` → ROS-стек запускается кнопкой в меню (или флагом `autostart_stack`, по умолчанию
выключен). Ручной перезапуск киоска после перезапуска стека **не нужен**: страница опрашивает
`/api/stack/status` раз в 2 с, подключает `/ros/ws` при `UP` и сама переподключается при
переходе в `UP`.

Повторы в `guide-kiosk-hdmi` остались как страховка от старта раньше launcher'а: при
`load-failed` и при гибели web-процесса WebKit скрипт перезагружает страницу каждые
`RETRY_S = 3` с.

### 2.2 Файлы адресов

- `/etc/guide-kiosk/url-hdmi` = `http://127.0.0.1:8089` — читает `guide-kiosk-hdmi`; если файла
  нет, скрипт использует `url`.
- `/etc/guide-kiosk/url` = `http://127.0.0.1:8090` — лицо; его читает `guide-kiosk-face`.

Раньше `url` указывал на `:8091` (страницу оператора), и `guide-kiosk-face` читал тот же файл, то
есть лицо ни одна служба не открывала. `install.sh` проверяет, что `guide-kiosk-face` действительно
читает `/etc/guide-kiosk/url`, печатает `grep -n url` и до записи адресов останавливается при
расхождении; ничего не меняя. Сами `guide-kiosk-face` и `guide_robot_face` не трогаются.

## 3. Сторона ROS: нода operator_ui — мост

Нода больше не отдаёт страницу, промо и вход. Это мост ROS ↔ HTTP на `127.0.0.1:8091`
(`network_mode: host`, поэтому виден с хоста). Она входит в `robot.launch.py`
(`hardware.launch.py` + `operator_ui.launch.py`), который запускает `start_stack.sh` из меню.
Запускать ноду вручную не нужно.

Параметры — `guide_robot_operator_ui/config/operator_ui.yaml`; полный список, API и токен —
`guide_robot_operator_ui/README.md`.

| Путь моста | Что отдаёт | Токен |
|---|---|---|
| `GET /ws` | кадры состояния сервер → клиент (по событию и heartbeat раз в 1 с) | нет |
| `GET /api/tours` | список туров | нет |
| `GET /api/media/{exhibit_id}`, `GET /media/*` | манифест и файлы слайдов экспоната | нет |
| `POST /api/tour/start`, `/api/tour/stop`, `/api/go_home`, `/api/localization/reset`, `/api/costmaps/clear` | команды роботу | **да** (`X-Bridge-Token`, иначе 403) |

Запросы с токеном присылает только launcher (заголовки `X-Bridge-Token` и `X-Operator`);
браузер к мосту напрямую не ходит: страница получает чтение через прокси `/ros/*` launcher'а
(GET + WebSocket), а команды — через `/api/op/*` после входа.

Кнопка «Старт» в меню отправляет `RunTour` текущего тура с флагами
`greet/narrate/confirm_between_stops/return_home = True`: они зашиты в ноде
(`operator_ui_node.py`). Для езды по одной точке это не подходит — там используется
`mission_cli tour --locations ... --no-greet --no-confirm --no-return-home`.

## 4. Страница: показ и меню

`scripts/jetson-launcher/web/` (`index.html`, `app.js`, `app.css`), отдаётся launcher'ом с
`Cache-Control: no-cache` на **всех** ответах, включая `GET /`.

1. **Медиа-слой** (`#media-layer`) — смонтирован всегда, чёрный фон, курсор скрыт: заставка
   «Экскурсовод», два слоя кроссфейда, титульная карточка, экран «Еду на базу», невидимый
   уголок для четырёх нажатий (открытие меню) в правом верхнем углу.
2. **Кнопка «Начать экскурсию»** — маленькая, полупрозрачная, внизу по центру, поверх показа.
   Видна, только если стек `UP`, есть свежая связь с `mission_fsm`, нет E-STOP, тура нет и
   название текущего тура найдено в `/ros/api/tours`. Нажатие открывает диалог «Начать
   экскурсию «…»?» с [Начать]/[Отмена], автоотмена через 15 с.
3. **Меню оператора** — открывается четырьмя нажатиями за 2 с в правый верхний угол и входом по PIN
   или RFID. Разделы «Экскурсия» (текущий тур, старт/стоп/домой), «Робот» (сброс локализации,
   очистка костмапов, статус supervisor и E-STOP), «ROS 2» (три проверки, состояние, последние
   30 строк лога, «Запустить»/«Перезапустить»). При `state != UP` первые два раздела неактивны.
4. **Плашки** — «E-STOP» и «Нет связи с mission_fsm» (второй показывается только при `UP`,
   чтобы мёртвый ROS не выглядел ошибкой). Плашки «Аутентификация отключена» больше нет:
   режима `mock` не существует.

Фон страницы и заставки чёрный. **Белый экран страница дать не может**; белое — это пустой
WebKit или отсутствие окна на компоситоре.

### 4.1 Что выбирает содержимое медиа-слоя

`updateMediaLayer()` в `app.js`; `always_promo` берётся из `/api/config` (ключ конфига
launcher'а, не константа в коде):

- `always_promo: true` (по умолчанию) — **промо крутится всегда**, и в простое, и во время тура;
- `always_promo: false`: тур не активен → промо; активен и связь с `mission_fsm` потеряна →
  замереть на последнем слайде; состояние `returning` → «Еду на базу»; иначе слайд по паре
  (`exhibit_id`, `chunk_index`);
- слайды и промо **никогда не показывают ошибок**: при мёртвом ROS просто крутится промо.

Открытое меню ставит видео на паузу.

## 5. Промо: путь картинки до экрана

### 5.1 Откуда берётся

```
guide_robot_operator_ui/promo/promo.yaml   ──┐  (исходный каталог, promo_dir в конфиге launcher'а)
guide_robot_operator_ui/promo/media/*.JPG  ──┤
                                             ↓
        launcher перечитывает promo.yaml при смене mtime (без сборки и рестартов)
                                             ↓
    GET /api/promo → {"items":[{id,kind,path,duration_s,caption}], "promo_interval_s":10.0, "rev":…}
                                             ↓
   app.js: манифест перезапрашивается на каждом обороте цикла; изменился rev → цикл перезапускается
                                             ↓
                        GET /promo/<path> → файл из promo_dir/media/
```

Формат `promo.yaml`: `items: [{id, kind: image|video, file, duration_s?, caption?}]`. Разбор
(`promo.py` launcher'а, бывший `lib/promo_io.py`) никогда не падает: битый YAML, отсутствующий
файл или неверный `kind` дают предупреждение в лог. Отсутствующий на диске файл всё равно
попадает в манифест — это заметно только на экране. Неудачный запрос манифеста оставляет
старые элементы.

В текущей петле шесть элементов (`IMG_1`…`IMG_6`, по 6 с; `hall.jpg` и `IMG_VIBORY.JPG` лежат в
`media/`, но не входят). `duration_s: 0.0` означает «взять `promo_interval_s`» (10 с); если
элемент один, та же картинка переклеивается с этим периодом. Масштабирование:
`object-fit: contain`, поля чёрные.

### 5.2 Как поменять картинки

```bash
# 1. положить файл
cp NEW.JPG guide_robot_operator_ui/promo/media/
# 2. вписать его в guide_robot_operator_ui/promo/promo.yaml
```

Всё. Через один оборот цикла картинка на экране. Сборка, рестарт ноды и рестарт киоска не
нужны. Промо отдаётся с хоста, поэтому крутится и при мёртвом ROS. Если launcher установлен не из
этого чекаута, `promo_dir` в `/etc/guide-launcher/config.yaml` должен указывать на каталог с
`promo.yaml`.

### 5.3 Что перезапрашивается

Промо — на каждом обороте цикла. Состояние стека и текущий тур — раз в 2 с. Список туров
(`/ros/api/tours`) — при переходе стека в `UP`. WebSocket `/ros/ws` подключается только при `UP`
и переподключается сам.

## 6. Слайды экспонатов

Работают при `always_promo: false`:

`/mission/state` даёт `exhibit_id` и `chunk_index` → страница просит
`GET /ros/api/media/<exhibit_id>` → нода зовёт два ROS-сервиса `content_server`:
`GetExhibitContent(mode="full")` за списком `chunk_id` и `GetExhibitMedia` за файлами → страница
выбирает элементы с совпадающим `chunk_id`, при отсутствии — общие для экспоната → файлы
отдаются по `/ros/media/<path>`. Медиа экспонатов идут через мост и нужны только во время тура.

Если у экспоната медиа нет (как у точек `vybory_*`), показывается титульная карточка с
названием экспоната. Манифесты кэшируются и на ноде, и в странице без инвалидации.

## 7. Вход оператора

- Четыре нажатия за 2 с в невидимый правый верхний угол открывают окно входа
  (считаются нажатия, а не удержание: тач-панель робота «отпускает» неподвижный
  палец через ~10 мс, поэтому долгое нажатие на ней не набиралось).
- Способы — `auth_backends` в конфиге launcher'а: `rfid` (карта на `/dev/rfid0`, секрет в файле
  `rfid_secret_file`; порт всегда принадлежит launcher'у) и `pin` (значение `operator_pin`, не
  короче 8 символов). Режима `mock` нет.
- Сессия — cookie `gl_session` (`HttpOnly`, `SameSite=Strict`), скользящее окно
  `session_ttl_s` (10 минут), продлевается только успешными запросами. Локаут: 10 неудач за 60 с.
- Все входы, выходы и команды пишутся launcher'ом в jsonl-журнал
  `~/.guide_robot/launcher/launcher_*.jsonl`.
- Публичный старт (кнопка на экране показа) — единственная команда без входа: сервер запускает
  только текущий тур и игнорирует `tour_id` клиента.

Подробности — `scripts/jetson-launcher/README.md`.

## 8. Что делать, если на большом экране не то

Порядок проверки от службы к железу.

```bash
# 1. launcher жив
systemctl status guide-launcher
journalctl -u guide-launcher -b

# 2. состояние стека (state и три проверки container / launch / bridge)
curl -s http://127.0.0.1:8089/api/stack/status

# 3. страница и промо
for u in / /static/app.js /static/app.css /api/config /api/promo; do
  curl -s -o /dev/null -w "$u %{http_code}\n" http://127.0.0.1:8089$u; done
curl -s http://127.0.0.1:8089/api/promo
curl -s -o /dev/null -w "%{http_code} %{size_download}\n" http://127.0.0.1:8089/promo/IMG_1.JPG

# 4. если стек не поднимается: меню → ROS 2 → лог, или
docker exec robo-guide-jetson-1 tail -n 50 /tmp/stack.log

# 5. службы экранов и их журнал
systemctl is-active weston-dlhdmi kiosk-hdmi kiosk-face
journalctl -u kiosk-hdmi -b | grep -v -iE "dbus|atspi|a11y|Deprecation|gdk_"
```

Трактовка:

| Симптом | Причина |
|---|---|
| В журнале `не загрузился ...: Connection refused` | `guide-launcher` не запущен: `systemctl status guide-launcher`; после старта браузер подхватит через 3 с |
| `state: DOWN`, крутится промо, кнопки «Начать экскурсию» нет | ROS-стек не запущен: меню → ROS 2 → «Запустить» |
| `STARTING`, потом `FAILED` | стек не поднялся за 120 с: лог стека; `start_stack.sh` пишет причину (нет `install/setup.bash` → `colcon build`) |
| `DEGRADED` | `ros2 launch` жив, а мост `:8091` молчит: нода `operator_ui` упала (нет токена, см. `/tmp/stack.log`) |
| Текст «Экскурсовод» | манифест промо пустой или все файлы битые: проверить `promo.yaml` и наличие файлов (`launcher` перечитает сам) |
| Картинка одна и не меняется | так и задумано: в `promo.yaml` активен один элемент |
| **Чисто белый экран** | это не страница (её фон чёрный): пустой WebKit, упавший web-процесс или отсутствие окна на компоситоре. Смотреть журнал `kiosk-hdmi` и `weston-dlhdmi`, наличие процессов `WebKitWebProcess`, `/dev/dri/card1`, и передёргивался ли донгл (`dmesg | grep fl2000`) |
| Экран мигает при касании, пропадает сигнал | аппаратная часть донгла — `scripts/jetson-display/README.md` |
| Лицо (глаза) не вернулось после «Перезапустить» | `face_node` живёт в `high_level_stack`: проверить `curl -s http://127.0.0.1:8090/`, лог стека |

## 9. Известные особенности и грабли

- Стек запускается **только кнопкой** (или `autostart_stack: true`); автоперезапуска нет. После
  перезагрузки Jetson экран показывает промо, пока оператор не нажмёт «Запустить».
- `restart` из меню сначала гасит `ros2 launch` через SIGINT и ждёт до 20 с, а не убивает
  контейнер: драйвер колёс держит последнюю скорость, а SIGKILL стоп-пакет не отправляет.
  Во время тура рестарт отклоняется (409 `robot_moving`): сначала «Стоп».
- Битые URL запоминаются страницей до перезагрузки страницы: один раз не отдавшийся файл
  выпадает из цикла. Для видео туда же ведёт событие `stalled`, то есть медленная отдача может
  выкинуть исправный файл.
- Сообщения об ошибках команд выводятся внутри меню оператора, поэтому на экране показа без
  входа их не видно (по замыслу).
- `always_promo: true` — временная мера, пока нет реальных медиа экспонатов. Пока флаг включён,
  путь слайдов тура на странице не исполняется, хотя мост его поддерживает.
- На Jetson часы могут уезжать (наблюдалось расхождение журнала и `date` почти на 12 часов) —
  фильтры `journalctl --since` тогда врут, надёжнее `-b`.
- `/etc/guide-kiosk/url` теперь адрес **лица** (`:8090`), а большой экран читает
  `url-hdmi`. Если `url-hdmi` пропал, `guide-kiosk-hdmi` откроет лицо на большом экране.
- Веб-сервис на `:8089` слушает только `127.0.0.1`; с ноутбука страницу можно открыть через
  `ssh -L 8089:127.0.0.1:8089`.
