01.11.2026: ручные положения: левый край около 2390, правый около 1305,
центр около 1780. При командовании целью 1521 энкодер оставался около 1635;
при цели 1583 и дополнительной команде 1523 — около 1674. Логи:
`/home/legion/Robot-recovery/furo-2015/robot_sessions/20261101/`.

По оригинальной панели `FormFuroSTester::button2_Click` выбранная ось 0x2B
передаётся методу `MobilityJoveTech.SetLimit` с partId 0x28. Метод DLL
строит кадр `FF FF 2F 0A 03 B1 <part> <min LE> <init LE> <max LE> <chk>`.
На роботе чтение обоих селекторов 0x28 и 0x2B дало 1650 / 2070 / 2600.
Одинаковый ответ не доказывает, относятся ли они к одной ячейке.

Для конкретного первого шага ниже подготовлены пакеты с **неизменными** init
и max. Они получены запуском исходной DLL локально через `MessageSending`,
без открытия порта и без отправки на робота:

```
min 1550: FF FF 2F 0A 03 B1 28 0E 06 16 08 28 0A 86
min 1650: FF FF 2F 0A 03 B1 28 72 06 16 08 28 0A 22
```

С разрешения владельца пакет `min 1550` однократно отправлен 01.11.2026.
Непосредственно перед записью чтение вернуло 1650 / 2070 / 2600, после —
1550 / 2070 / 2600. Команда положения 1550 затем довела энкодер до примерно
1575–1581. Журнал транзакции сохранён в каталоге сессии, в подкаталоге
`limit-change-1550`. Обратный пакет не отправлялся.

Прошивка контроллера не изучена: сохранение лимита после перезагрузки,
отсутствие побочных эффектов и работоспособность отката **не доказаны**.
Дальнейшие изменения лимитов требуют отдельного согласования владельца.
